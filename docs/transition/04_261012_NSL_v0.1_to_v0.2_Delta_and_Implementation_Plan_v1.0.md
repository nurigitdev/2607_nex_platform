
# NSL v0.1 → v0.2 Delta Matrix & Implementation Plan v1.0

**Phase:** P3 — NSL v0.1 As-Built & v0.2 Delta  
**v0.1 baseline:** `nurigitdev/2608_nsl` tag `v0.1` / `803f22aadc3946a48b05472c80b60fe11d9d9554`  
**v0.2 target:** NSL v0.2 Frozen Set + Agent↔NSL Integration Contract v1.0  
**Predecessor:** NSL v0.1 independent As-Built analysis completed  
**Goal:** Fix the code path from the actual v0.1 repository to the Frozen v0.2 target without redesigning either baseline.

---

## 1. Executive Decision

The v0.2 target should **not** be implemented as a rewrite of NSL v0.1.

The Frozen v0.2 design itself explicitly preserves the real v0.1 repository structure and requires behavior-preserving, hotspot-only refactoring rather than a big-bang package reorganization.

The recommended implementation model is:

```text
NSL v0.1
Compiler / IR / Runtime / Security / Audit / Replay / NSP Trust
                         │
                         │ preserve and extend
                         ▼
NSL v0.2
same deterministic kernel
+ Controlled WRITE protocol
+ Approval suspend/resume semantics
+ BusinessOperationId / Idempotency
+ Commit / Verification
+ Agent↔NSL runtime integration
```

The dominant disposition is therefore:

```text
REUSE existing v0.1 foundations
+
EXTEND additive contracts
+
NEW controlled-write components
```

not `REPLACE`.

## 3. Core Delta

The major semantic addition is:

```text
v0.1
READ
→ CHECK
→ EMIT
```

becomes, for a v0.2 controlled-write Skill:

```text
READ
→ CHECK
→ PreWriteEligibility
→ WriteIntent Freeze
→ Approval Request
→ durable Checkpoint
→ WAITING_FOR_APPROVAL
→ Worker release
→ Agent/Platform Human Workflow
→ RESUME
→ Approval Evidence binding verification
→ current Policy / Business Preconditions
→ IdempotencyKey
→ durable WRITE_REQUESTED
→ atomic Canonical WRITE
→ CommitState
→ Post-Write Verification
→ EMIT / Result
```

This is not a new `write` keyword alone. It is an end-to-end side-effect protocol.

## 4. Direct REUSE

### 4.1 Signed NSP Trust Boundary

The strongest direct reuse is:

```text
NspBuilder
NspVerifier
Ed25519 signer/verifier
Trusted key store
VerifiedNspPackage
exact Skill identity/version/semantic hash
```

Frozen v0.2 explicitly says Production WRITE must reuse this existing Signed NSP trust boundary rather than creating a second `.nso` signature system.

**Decision:** REUSE.

### 4.2 Principal / Data Policy

Existing:

```text
ExecutionPrincipal
PrincipalVerification.VERIFIED
Tenant / Subject / Actor Type / Roles / Scopes
AuthContextRef
DataHandlingPolicy
```

remain required in v0.2.

**Decision:** REUSE.

### 4.3 READ/CHECK/EMIT Runtime

The current deterministic read-only execution path remains the compatibility baseline.

**Decision:** REUSE + Regression Lock.

### 4.4 Audit / Snapshot / Replay Foundations

Current protected snapshots, tenant checks, hash references and ReplayToolExecutor are valuable foundations.

**Decision:** REUSE, then EXTEND with v0.2 control evidence.

## 6. New v0.2 Runtime Components

The following have no real v0.1 production equivalent and should be implemented as new, typed components.

### 6.1 Approval / Suspension

```text
ApprovalRecord
ApprovalEvidence
ApprovalPort
ApprovalCoordinator
CheckpointPort
ExecutionCheckpoint
StatementSuspended
```

NSL owns approval semantics and evidence validation.

It does **not** own:

```text
approver routing
UI
notification
decision workflow
Resume Job enqueue/scheduling
```

Those belong to Agent/Platform.

### 6.2 Business Write Identity

```text
BusinessOperationId
ApprovalRequestId
WriteNodeId
ToolInvocationId
IdempotencyKey
PayloadHash
WriteIntentHash
```

`BusinessOperationId` comes from Agent/Platform runtime and must remain stable across:

```text
Suspend
Resume
Runtime re-execution
Reconciliation
```

### 6.3 Write Guard

New pre-write gating combines:

```text
CHECK status
Approval Evidence
Current authorization/policy
Tool contract fingerprint
Package trust
Business Preconditions
Replay guard
Idempotency readiness
```

No single ALLOW may override another required DENY.

### 6.4 Write Execution

New side-effect port:

```text
WriteExecutionPort
```

must be separate from the normal READ `ToolExecutionPort`.

Typed outcome:

```text
WriteCommitted
WriteNotCommitted
WriteCommitUnknown
```

### 6.5 Durable Write Evidence

Before the provider call:

```text
WRITE_REQUESTED
```

must be durably recorded.

No durable evidence:

```text
→ Provider WRITE = 0
```

### 6.6 Commit / Verification

Commit and verification are separate:

```text
CommitState
!= VerificationStatus
```

`COMMITTED + Verification FAILED/UNKNOWN` must never be interpreted as `NOT_COMMITTED`.

## 7. Runtime Refactoring Strategy

The existing `RuntimeEngine` is valuable and should remain the single semantic kernel.

Recommended structure:

```text
RuntimeEngine
├─ existing READ evaluator
├─ existing CHECK / EMIT
├─ StatementExecutor v0.2
├─ ApprovalCoordinator        NEW
├─ CheckpointCoordinator      NEW
├─ WriteIntentBuilder         NEW
├─ WriteGuard                 NEW
├─ IdempotencyKeyFactory      NEW
├─ WriteExecutionPort         NEW
└─ PostWriteVerifier          NEW
```

This keeps the proven v0.1 deterministic evaluator while isolating side-effect complexity.

**Disposition:** `REFACTOR + EXTEND`, not replacement.

## 8. ExecutionContext Evolution

v0.1 state remains:

```text
inputs
runtime_context
variables
check frames
checks
outputs
resource meter
principal
data policy
```

v0.2 adds:

```text
BusinessOperationId
ApprovalStore
WriteJournal
IdempotencyState
CheckpointState
ControlEvidence
```

These are execution-local state containers, not service locators.

The following must **not** be placed into ExecutionContext:

```text
Tool service
Write provider
Approval workflow service
Queue
Checkpoint repository implementation
Package signature verifier
Resume scheduler
```

## 9. AE Integration Contract Evolution

### v0.1

```text
SkillExecutionJob
  execution_id
  skill id/version
  expected semantic hash
  structured inputs
  provenance
  runtime context
  verified principal
  data policy
```

### Frozen target

The Agent↔NSL contract introduces a richer invocation lifecycle:

```text
AgentExecutionId        external parent runtime identity
NSLExecutionId          one NSL NEW→WAIT→RESUME lifecycle
BusinessOperationId     stable business operation identity
mode                    NEW | RESUME
VerifiedSkillArtifact
typed projected inputs/context
approval/checkpoint evidence on RESUME
```

Critical invariant:

```text
AgentExecutionId
!= NSLExecutionId
!= BusinessOperationId
```

### Migration recommendation

Do **not** simply rename `execution_id` to `AgentExecutionId`.

Instead:

1. preserve v0.1 worker/runtime execution semantics internally;
2. introduce the Frozen `SkillExecutionRequest` at the integration boundary;
3. map the stable NSL lifecycle identity to an explicit `NSLExecutionId`;
4. carry `AgentExecutionId` only as correlation/parent identity;
5. carry `BusinessOperationId` as a separate business-effect identity;
6. support `NEW` and `RESUME`.

**Disposition:** REFACTOR + EXTEND with a compatibility adapter.

## 10. Worker / Queue Boundary

The v0.1 `SkillExecutionWorker` is a strong reusable component.

However:

```text
InMemoryJobDispatcher
```

is only a contract fake.

Production dispatch in the target must use the Platform/AE durable JobQueue.

Therefore:

```text
SkillExecutionWorker       → EXTEND
InMemoryJobDispatcher      → REUSE for tests only
Production dispatch adapter→ NEW in Platform integration
```

Long Approval WAIT must release the Worker; a later Platform Resume Job invokes NSL in `RESUME` mode.

---

## 11. Replay Evolution

v0.1 Replay already prevents live Tool calls by substituting recorded Tool results.

v0.2 extends this rule:

```text
Replay
= no live Tool provider for recorded effects
+ no live Approval decision
+ no live policy decision that changes historical meaning
+ no live WRITE
```

Replay must snapshot/reuse:

```text
Approval Evidence
Package Trust Evidence
Write Outcome
Verification Outcome
```

**Disposition:** EXTEND existing Replay architecture.

---

## 12. Error / Outcome Evolution

v0.1 already has typed execution statuses and Tool errors.

v0.2 must add semantic outcomes that cannot be collapsed into generic error:

```text
WAITING_FOR_APPROVAL
RECONCILIATION_REQUIRED
WriteCommitUnknown
IDEMPOTENCY_CONFLICT
Approval rejected/expired/invalid
Verification FAILED/UNKNOWN after COMMITTED
```

The most important rule is:

```text
UNKNOWN_COMMIT_STATE
!= retryable generic Tool failure
```

It must hand off to Platform reconciliation.

---

## 13. Package / Trust Decision

No new signing architecture is required.

Recommended target:

```text
Signed NSP
→ existing NspVerifier
→ existing trusted publisher verification
→ Verified Package
→ Platform/Agent Skill Artifact Gateway
→ VerifiedSkillArtifact / PackageTrustEvidence
→ NSL Runtime preflight
```

This is primarily an **adapter/evidence-shape extension**, not a crypto rewrite.

---

## 14. Quality / Regression Strategy

Every v0.2 change must retain v0.1 quality evidence.

Mandatory baseline:

```text
all v0.1 regression tests
statement coverage >= 95%
branch coverage >= 90%
performance acceptance
negative acceptance
traceability certification
```

Add v0.2 negative cases:

```text
WRITE using READ Tool
WRITE without Approval
Approval↔WRITE mismatch
Approval replay/hash mismatch
WRITE in FOREACH
more than one WRITE
non-atomic WRITE Tool
idempotency unsupported
same key/different payload
untrusted package
checkpoint/publish crash
UNKNOWN commit no blind retry
COMMITTED + Verification FAILED no re-WRITE
Replay no live WRITE
```

## 15. Implementation Sequence

Recommended sequence from the real v0.1 codebase:

### NSL-D1 — Compatibility Lock

- freeze v0.1 READ regression
- record module/API fingerprints
- no semantic changes

### NSL-D2 — Tool Contract + Shared Value Types

Add:

```text
WRITE semantics
BusinessOperationId
ApprovalRequestId
PayloadHash
IdempotencyKey
CommitState
VerificationStatus
```

### NSL-D3 — Grammar / AST / IR 1.1

Add Approval/Write nodes and strict compiler constraints.

### NSL-D4 — Additive Runtime State

Extend ExecutionContext / ExecutionResult without changing READ behavior.

### NSL-D5 — Approval + Checkpoint

Implement:

```text
WriteIntent Freeze
→ ApprovalRequestId
→ durable checkpoint
→ publish
→ WAITING_FOR_APPROVAL
```

### NSL-D6 — RESUME Validation

Restore checkpoint and validate:

```text
Approval Evidence
BusinessOperationId
ApprovalRequestId
PayloadHash
WriteIntentHash
trust/current policy
```

### NSL-D7 — Controlled WRITE

Add:

```text
WriteGuard
IdempotencyKeyFactory
WriteEvidencePort
WriteExecutionPort
CommitState
```

### NSL-D8 — Post-Write Verification / Reconciliation Evidence

Add typed VerificationStatus and unknown-commit handoff.

### NSL-D9 — Replay / Audit Extension

No-live-write replay and control-evidence snapshotting.

### NSL-D10 — Agent/Platform Adapter

Integrate the Frozen `SkillExecutionRequest NEW/RESUME` contract with the actual AE durable runtime.
