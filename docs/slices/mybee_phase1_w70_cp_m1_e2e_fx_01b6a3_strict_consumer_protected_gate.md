This Slice closes the provider-neutral consumer and protected evidence boundary
for EOS allocation-to-Project-P&L activation. It adds no M1 fixture, fixed
Project set, default allocation ratio, Plan ID, or business fallback. The
consumer accepts only tenant, company, verified Batch, and correlation
identity and treats EOS as the sole projection authority.

## Strict Consumer Boundary

`NexProjectPnlRefreshClient` invokes the canonical product operation:

```text
POST /internal/v2/finance/cost-allocation-batches/{batch_id}:refresh-project-pnl
Operation: FINANCE.PROJECT_PNL.REFRESH_FROM_ALLOCATION
```

The consumer enforces all of the following before returning a result:

- exact schema, operation, tenant, company, and Batch identity;
- exact response and projection field sets;
- UUID, Project Code, positive version, and semantic hash syntax;
- only `CREATED` or `EXACT_REPLAY` dispositions;
- only `VERIFIED` and `CURRENT` projection results;
- non-empty, duplicate-free, deterministic Project ordering; and
- independent recomputation of the domain-separated `refresh_hash`.

Transport errors are normalized into typed fail-closed consumer errors.
Successful projections are returned as immutable mappings and tuples. The
HTTP transport uses a bounded timeout, a signed EOS service token, explicit
tenant/company/correlation headers, and no request body.

## Installed AE Composition

`project_pnl_refresh_runtime.py` is a thin installed boundary. It resolves the
canonical EOS base URL, startup-issued or configured service token, and a
bounded timeout, then composes the generic consumer. Readiness reports only
configuration metadata and a semantic hash; it exposes neither secrets nor
business content and states that no business defaults are included.

The module is admitted as active AE product code. Explicit AE ownership and
coverage inventories were advanced from 181 to 182 modules and from 171 to
172 active-product modules. No compatibility or quarantine exception was
added.
