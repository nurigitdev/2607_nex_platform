# P6.5-S2 Live Intent Candidate Generation

**Status:** IMPLEMENTED
**Date:** 2026-10-16
**Predecessor:** P6.5-S1 Thin AE-to-MO Generation Client

## Scope

P6.5-S2 activates only the INTENT semantic stage:

```text
untrusted user prompt
-> exact ae.intent_resolution.default/v1 binding snapshot
-> thin AE-to-MO generation client
-> closed IntentCandidate JSON
-> deterministic schema/authority/policy validation
-> model-revision calibration
-> deterministic IntentDecision
-> WorkIntent in required mode only
```

This Slice does not wire the stage into `POST /api/v1/chat/interactions`, add a
candidate table, persist candidate payloads, resolve AgentContext, build an
AgentPlan, or create an ExecutablePlan/RuntimeJob. S5 owns route orchestration,
persistence, resume, and compilation.

## Structure

The implementation keeps distinct responsibilities:

- `semantic_candidates.py` owns the reusable stage/model-specific calibration
  registry and common fail-closed error type for INTENT/CONTEXT/PLAN.
- `intent_candidate_generation.py` owns INTENT prompt resolution, untrusted
  input projection, candidate parsing, deterministic admission, and WorkIntent
  handoff.
- `intent_policy.resolve_validated_intent_candidate()` remains the canonical
  code path that transforms an admitted suggestion into `IntentDecision`.
- `work_intent.build_work_intent_from_decision()` remains the only WorkIntent
  builder used by this path.

No database migration is required. The additional immutable prompt seed uses
the existing Prompt Registry tables and insert-or-verify behavior.

## Prompt Binding

S2 adds:

```text
binding_key = ae.intent_resolution.default
purpose = intent_resolution
version = v1
role = system
candidate_schema = p65.intent_candidate.v1
```

The stage captures binding ID, template version ID/version, content SHA-256,
and rendered prompt hash before provider execution. A pointer change after
capture cannot alter the in-flight version.

The raw user prompt is sent only as an untrusted user message and is not stored
in stage result provenance or smoke evidence. Its complete semantic input is
represented by `input_context_hash`.

## Candidate Admission

The closed validator accepts only:

```text
schema_version
intent_label
suggested_execution_mode
entity_selectors[]
parameter_candidates[]
clarification
confidence
```

It rejects malformed JSON, unknown fields/schema, unsupported execution mode,
non-finite or malformed confidence, duplicate/unbounded values, authority
fields, and prompt-control language. Tenant, principal, owner, project, role,
permission, capability version, executor, provider endpoint, API key, model
path, and approval fields are explicitly forbidden at every nesting depth.

Validated selector and parameter suggestions are not copied into WorkIntent.
S3 may use bounded hints, but its trusted context resolver remains authoritative.

## Deterministic Authority

`IntentCandidate.suggested_execution_mode` is limited to the four existing
compatibility modes. Deterministic policy then applies trusted controls:

- an explicit trusted execution mode cannot be overridden;
- retrieval admission promotes `GENERAL_ANSWER` to `GROUNDED_ANSWER`;
- task category, retrieval/template requirements, decision hash, and raw-prompt
  exclusion are generated by AE code;
- only a successful `required` result creates WorkIntent;
- `shadow` produces `SHADOW_ONLY` evidence and no WorkIntent;
- low confidence or requested clarification creates no WorkIntent.

`authorized_resource_context_available` is a boolean availability assertion,
not a resource identity or authority grant. It supports the Golden fixture
without introducing Enterprise OS, Project, WC, or PA semantics.

## Calibration

Policies are deployment-projected through:

```text
NEX_AE_P65_SEMANTIC_CALIBRATION_POLICIES_JSON
```

Each exact policy is selected by:

```text
semantic_stage + model_profile + model_ref
```

and records policy version/ref, minimum confidence, Golden evidence ref, and
adversarial evidence ref. Duplicate identities and malformed/missing required
policies fail closed. There is no model-independent confidence default.

The protected S2 smoke used a provisional `p65.s2-smoke.1` policy with threshold
`0.5` solely to prove runtime selection. It is not a production threshold.
The S6 provider/adversarial matrix and S7 acceptance must supply reviewed
calibration evidence before required-mode release.

## Digest Reconciliation

CA01 defines `candidate_hash` as `sha256:<hex>` and the exact provider output
digest as bare lowercase SHA-256. S2 corrects the S1 normalized result and
protected smoke assertion accordingly:

```text
candidate_hash          = sha256:<64 hex>
provider_output_sha256  = <64 hex>
```

Both use the shared `nex_runtime.semantic_hashes` implementation.
