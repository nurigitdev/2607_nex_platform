## Authoring Method

The 30 READY packages preserve the reviewed v2 business questions and source
passages. Their relevance grades are mapped explicitly:

| v2 relevance grade | v3 evidence role |
| --- | --- |
| `STRONG_POSITIVE` | `PRIMARY_ANSWER` |
| `ACCEPTABLE_POSITIVE` | `SUPPORTING_ANSWER` |
| `HARD_NEGATIVE` | `HARD_NON_ANSWER` |
| `EASY_NEGATIVE` | `EASY_NON_ANSWER` |

The 30 LOW_CONFIDENCE packages are independently authored questions in the
same scenario domains. They model plausible production requests for details
that the admitted corpus does not establish, such as an exact retry count,
schedule, threshold, code format, UI presentation, or deployment parameter.
Each package contains:

1. a close but insufficient `HARD_NON_ANSWER`;
2. a related policy `RELATED_NON_ANSWER`;
3. an unsupported and overconfident `CONTRADICTORY_NON_ANSWER`;
4. an unrelated `EASY_NON_ANSWER`.

The LOW_CONFIDENCE questions and candidate passages do not copy any v2 query
or passage. They are not generated by negating READY text or swapping binary
labels.

## Safety Boundary

- v1 and v2 contents were not modified.
- No provider-specific score sign, threshold, or feature weight is encoded in
  the dataset.
- Candidate labels are source truth used only for evaluation.
- Collection must issue one retrieval/rerank request over all four candidates.
- Holdout results must not influence feature design, weights, or thresholds.
- A model or policy revision requires a separately bound evidence run.
