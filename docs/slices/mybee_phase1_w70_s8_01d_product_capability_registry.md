## Decision

S8-01D creates an immutable AE Product Capability Registry release for W70
without converting the S8-01C descriptor-only packs into executable runtime
capabilities.

The release separates two concepts:

- `active_registrations` contains the exact immutable Golden A registration
  copied from the v1 predecessor; and
- `candidate_admissions` contains the 18 D04/D12 operation identities with
  exact pack, binding catalog, contract, and candidate bundle locks.

Candidate admissions are not `ProductCapabilityRegistration` objects, contain
no fabricated compiled Skill semantic hash, and cannot be returned by the
active registry resolver. Every candidate remains `runtime_selectable=false`
and `compile_state=PENDING_S8_01E`.

This preserves the existing runtime invariant that an executable
`ProductCapabilityRegistration` is always `ACTIVE`, compiled, exact-version,
and bound to a signed trusted Skill. S8-01E owns that compile and trust
promotion boundary.

## Registry Release

The new release is:

```text
deployment/environments/ae-product-capability-registry.v2.json
```

It contains:

- one immutable active Golden A registration;
- 18 canonically ordered W70 candidate admissions;
- 16 `CANDIDATE`, one `DEFERRED`, and one `ACTIVE_COMPATIBILITY` state;
- the exact v1 predecessor byte and semantic registry hashes; and
- the exact multi-bundle-set byte and content hashes.

The release hashes are:

```text
registry bytes:
sha256:ccb0727a1243354f0ca8fe090d686abf7af94d0677e3a236ddb389b348841b5d

registry semantic content:
sha256:c0d73447f00aef5cebaeb8072dea8c39c000aca94c0d384c55547da95dcf683e
```

`nex_ae_api.product_capability_releases` verifies the predecessor, active
registration projection, candidate ordering and hashes, alias ownership,
non-selectability, bundle membership, pack identity, and exact referenced
bytes. It exposes candidate lookup for admission audit only; it provides no
runtime selection or capability merging path.

Each candidate lock pins the S8-01C pack manifest and catalog bytes and

```text

runtime_selectable=false
signature_status=NOT_SIGNED
compile_state=PENDING_S8_01E
activation_requires=S8_01E_GATE
```

`nex_runtime.nsl_bundle_set` rejects changed, missing, reordered, duplicated,
escaping, signed, compiled, unsupported, or digest-mismatched bundle records.

## Deterministic Generation

`scripts/quality/build_w70_product_capability_registry.py` deterministically
derives all four artifacts from the admitted inventory, S8-01C packs, v1
registry, historical bundle lock, and NSL wheel lock.

```text
python scripts/quality/build_w70_product_capability_registry.py --write
python scripts/quality/build_w70_product_capability_registry.py
```

The default check mode fails when any checked-in artifact differs from the
canonical generated bytes.

## Deployment Boundary

S8-01D intentionally does not change:

- `NEX_AE_PRODUCT_CAPABILITY_REGISTRY_PATH` in Docker Compose;
- the AE runtime Containerfile registry path;
- the active one-Skill bundle environment;
- capability snapshots or dispatch selection;
- any database, API, NSL source, compiler, runtime, or trust key; or
- the seven status-only response-contract blockers.

Installed runtime therefore continues to use
`ae-product-capability-registry.v1.json`. The v2 release is immutable candidate
admission evidence until S8-01E passes.
